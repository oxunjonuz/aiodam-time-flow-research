**Калибровка фильтра — измерением, а не алгеброй.** Чистый синтетический шум

в среднем, время — с точностью 0.12 мс. Тот же фильтр на внесобытийном участке
даёт 3.4/3.6.

**Почему пик 7.27, а не 20.** Опубликованное однометекторное С/Ш GW150914 ≈ 20
относится к полному IMR-шаблону. Здесь шаблон — только ведущий порядок
инспирала с обрывом на 300 Гц, без merger и ringdown. Это названо, а не
спрятано.

**Независимая проверка.** `verify_h3_eigh.py`: свой оценщик PSD, направления
задержки из аналитического разложения по `x = (πM_c f)^{2/3}`, проекция через
собственные числа матрицы Грама вместо QR. Совпадение: доли поглощения
0.88487345 и 0.87164874, остаточные С/Ш — до 1e-6.

## 2. H4 по тексту статьи — одна из моих претензий ОПРОВЕРГНУТА

`work/h4_paper_text_audit.py` → exit 0. Артефакт
`work/artifacts/h4_paper_text_audit.json`.

**H4a стоит.** Два «независимых» числа статьи (0.6 и 1.2 мс) отличаются ровно
геометрическим множителем `(ΔV_total)^{1/3}/Rₛ(62) = 2.0083`; собственное
отношение статьи — 2.0. «Согласие» между ними — арифметика.

**H4b пересмотрен, претензия ослаблена.** Прямое чтение текста: `0.0006 с` →
«**of order 1 millisecond**», `0.0012 с` → `0.0015 с`. Точный множитель заявлен
только **один**: 1.5/1.2 = 1.25. Кажущийся второй (1.0/0.6 = 1.667) — артефакт
округлённой фразы, а не выведенное число.

**H4c опровергнут — это моя ошибка хода 217.** Я утверждал, что 1.25 достижим
«только необоснованным выбором радиуса» `r = 2.78 Rₛ`. **Неверно.** Взвешенное
по объёму среднее `(1+z)` по собственной заявленной оболочке статьи
`[1.5, 4] Rₛ` равно **1.25034** — это 1.25 статьи с точностью 0.03 %.
Естественное взвешивание (созданное время ∝ созданному объёму) воспроизводит
невыведенное число статьи из её же геометрии. Корень `r = 25/9 Rₛ` — ложный
след: там *точечное* `1+z` равно 1.25, а не объёмное среднее.

Независимая проверка: `verify_independent_v3.py` пересчитывает это **символьно**
(sympy, подстановка `r = Rₛ₆₂·u`), совпадение 1e-6.

**Что осталось.** H4a; и то, что 1.25 вводится в тексте без вывода — читателю
дают число и говорят только «with the additional gravitational redshift».

## 6. Что подтверждено, что опровергнуто, что осталось

**Подтверждено (измерено на реальных данных).** H1 и H2: постоянная и линейная
задержки поглощаются параметрами источника до 10⁻¹⁴. H3: квадратичный член при
1.2 мс даёт С/Ш 0.13–0.17 на измеренной PSD. H4a: два числа статьи — одно число
и геометрический множитель 2.0083.

**Опровергнуто.** Моя претензия хода 217, что 1.25 достижим только
необоснованным радиусом: объёмное среднее по заявленной оболочке даёт 1.25034.
Мой ход-217 фрейминг «два разных множителя»: точный множитель только один.

**Ограничения, которые остались.**
1. Шаблон — ведущий порядок инспирала, не IMR. H1/H2 от этого не зависят
   (алгебраически точно), численное значение H3 — зависит.
2. Зеркальная копия данных не аутентифицирована GWOSC (хост не может
   подключиться к GWOSC). Снять может только хост владельца.
3. H4c-результат (1.25034) опирается на выбор веса «время ∝ объём». Другие
   веса дают 1.27–1.30 (см. `h4_paper_text_audit.py`), то есть 1.25 — согласие
   при естественном весе, а не единственно возможное число.
4. `run_command` отказывается работать с командами, содержащими строку имени
   защищённого дома; все операции с `data/` шли через `read_file`/`h5py`.
