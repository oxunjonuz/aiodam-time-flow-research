## 1. Исправление H4 (найдено владельцем)

**Дефект.** Отчёт §5/H4 утверждал, что множитель 1.25 «не попадает ни при каком
выборе радиуса» из диапазона 1.5–4.0 Rₛ. **Это было неверно.** Код
`h4_paper_arithmetic.py` (строки 99–100) проверял `1+z` лишь в **четырёх**
точках `{1.5, 2, 3, 4}`, где `1+z` = {1.732, 1.414, 1.225, 1.155}, и по этим
четырём пробам объявлял недостижимость. Уравнение `1+z(r) = 1.25` имеет корень
`r/Rₛ = 1/(1 − 1/1.25²) = 2.7778`, и он **лежит внутри** `[1.5, 4]`.

**Худшая часть.** v1 сам вычислял `r_needed = 2.7778` и сам печатал диапазон
`[1.5, 4]` в том же артефакте — но **не сравнивал их**. Два числа стояли рядом
в одном JSON, а вердикт противоречил обоим. Тот же класс, что и дефекты harness:
утверждение, которое никто не исполнял.

**Правка (v2).** Скан всего интервала (20001 точка) находит корень; самопроверка
`scan_sees_1.25_on_stated_range`; негативный контроль — тот же скан на `[1.5, 2.5]`
(корень не содержит) обязан дать `contains_1.25 = false`. Вердикт переписан:
1.25 **достижим**, но **только** при `r/Rₛ = 2.78`, который статья не называет и
ничем не выделяет. Претензия ослабевает с «невозможно произвести» до
«производится только необоснованным выбором радиуса».

**Что НЕ изменилось.** Главный результат H4 (0.6 и 1.2 мс — не независимые
оценки, отличаются геометрическим множителем 2.008) не затронут: он не
использует красное смещение.

**Проверка.**
- `python3 h4_paper_arithmetic.py` → exit 0, все 4 самопроверки true.
- `python3 verify_h4_independent.py` → `H4_INDEPENDENT_CONFIRMED`. Файл **не
  импортирует** аудируемый скрипт; решает уравнение **символьно** (sympy,
  корень `25/9`), читает только артефакт.
- **Негативный контроль:** порча корня в артефакте (2.7778 → 3.0) → верификатор
  краснеет (`H4_INDEPENDENT_DISAGREES`, exit 1).
- **Негативный контроль №2:** архивный v1 на том же входе воспроизводит ложный
  вердикт `False` при `r_needed = 2.7778` внутри `[1.5, 4]`.
- Оригинал сохранён: `work/archive/h4_paper_arithmetic_v1_original.py`
  (sha256 `15f151c1768f52925341449d34ab4dd9443ff51d2a596d898b2d6a8c1aa8ea13`).

## 2. Вариант Б — стрела времени из граничных условий

**Файл:** `work/lean/PastHypothesis.lean`. Формализован логический скелет
гипотезы прошлого: стрела не берётся из T-симметричной динамики, а требует
граничного условия, **нарушающего** T-симметрию.

| теорема | содержание |
|---|---|
| `rev_isTraj` | обращение траектории — снова траектория |
| `arrow_vanishes_on_symmetric` | само-обратная траектория несёт нулевую стрелу |
| `rev_allowed_of_invariant` | T-инвариантная граница сохраняет замкнутость |
| `arrow_sum_zero` | **вывод:** на замкнутом семействе стрела суммируется в 0 |

**Анти-вакуумность (обязательна).** `demo_arrow_vanishes`; `paramArrow_isArrow`
+ `paramArrow_ne_zero` (ненулевая стрела реально существует); `demo_closure_is_the_line`
— **решающий свидетель**: одна стрела на двух семействах даёт сумму `0`
(замкнуто) против `2` (не замкнуто), то есть гипотеза замкнутости — ровно та
линия, что разделяет вывод; `Bfuture_not_invariant` + `demo_boundary_breaks_reversal`
— граница `{n | 0 ≤ n}` не T-инвариантна.

**Проверка.** `sh verify_lean.sh` → rc=0, `NO_SORRY_NO_AXIOM`; аудит аксиом всех
12 теорем — только `[propext, Classical.choice, Quot.sound]`; скан
`native_decide`/`unsafe`/`implemented_by` — пусто. **Негативные контроли:**
удалить `TRSymmetric` из `rev_isTraj` → ошибка компиляции; удалить замкнутость из
`arrow_sum_zero` → 4 ошибки; подсунуть `sorry` → скан ловит.
